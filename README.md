# ZCode Development Pipeline

Конвейер разработки ПО на субагентах ZCode: от брифа до приёмки, с тройным ревью,
QA, базой знаний («Карпати-вики») и инициализацией проектов.

## Состав системы

- **12 субагентов** (`~/.zcode/agents/`): `initializer` → `briefer` → `architect` → `tech-lead` → `tech-writer` → `developer` → ревью `security-review` → `goal-review` → `code-review` → `qa` → `manager` → `summarizer`.
- **Slash-команда** `/init-project` (`~/.zcode/commands/init-project.md`) — запуск инициализатора.
- **Глобальный AGENTS.md** (`~/.zcode/AGENTS.md`) — персональные правила + указатель на базу знаний проектов.
- **Бандл** `zcode-pipeline-bundle.md` — переносимый снимок всего перечисленного для чистых экземпляров ZCode.

Источник правды — живые файлы в `~/.zcode/`. Этот репозиторий хранит бандл,
скрипт его сборки и документацию изменений.

## Установка на чистую машину

1. Скопируйте туда `zcode-pipeline-bundle.md` и откройте его в ZCode.
2. Скажите: «установи по этому документу».
3. Главный агент создаст все файлы (по AGENTS.md спросит обращение и язык),
   затем перезапустите сессию ZCode.
4. Проверка: 12 агентов в списке + команда `/init-project`.

## Цикл обновления (обязателен)

1. Правки вносятся **только** в живые файлы `~/.zcode/agents/*.md`, `commands/`, `AGENTS.md` — не в бандл.
2. Пересборка: `python3 scripts/build_bundle.py` (из корня этого репозитория).
   Скрипт падает, если находит персональные данные или ломает разметку — не обходить.
3. Коммит + запись в `CHANGELOG.md` (что изменилось, почему, дата).
4. Для вех — тег (`v1.0`, `v1.1`, …).

## Справка: как ведёт конвейер агент-координатор

Порядок: Инициализатор (по запросу, этап 0) → Брифер → Архитектор → Техлид → Техписатель →
Исполнитель → Ревью (Security → Goal → Code, циклы до полного одобрения) → QA → Менеджер
(ACCEPTED/REJECTED) → Саммарйзер (база знаний `.ai/docs/`) → коммит (координатор).

Полная справка — в шапке `zcode-pipeline-bundle.md` (раздел «Как работает конвейер»).

Артефакты в проекте: `.ai/briefs|architecture|decomposition|tasks|reviews|qa|docs|guides`.
Статусы задач: `created → in_progress → implemented → reviewed → tested → accepted | rejected`.

## Структура репозитория

```
zcode-pipeline-bundle.md   # артефакт сборки (не редактировать руками)
scripts/build_bundle.py    # сборщик бандла из живых файлов
CHANGELOG.md               # история изменений системы
README.md                  # этот файл
```
