# ZCode Pipeline

[English](README.en.md) · [Русский](README.ru.md) · [中文](README.zh.md) · [К краткому README](README.md)

Многоагентный конвейер разработки для [ZCode](https://z.ai): превращает сырой запрос пользователя в принятую, проверенную доработку через цепочку специализированных субагентов — с обязательными брифом, архитектурой, декомпозицией, тройным ревью, QA и живой базой знаний.

## Какие задачи решает

| Типичные проблемы LLM-агентов | Что enforcing'ит конвейер |
|---|---|
| угадывают неясные требования | **Брифер** задаёт интерактивные раунды вопросов до полного брифа; следующие агенты не стартуют без него |
| прыгают в код без проектирования | **Архитектор** выдаёт решение *плюс обязательные рекомендации* каждому следующему агенту |
| пишут расплывчатые мега-задачи | **Техлид** декомпозирует до задач с контрактами; **Техписатель** делает самодостаточные файлы задач (inline-правила, target shape, критерии приёмки) |
| заявляют «тесты проходят», не запуская их | **Исполнитель** обязан подтвердить каждый факт реальным выводом команд; ревьюеры проверяют независимо |
| штампуют одобрения своей работы | три независимых read-only ревью — **Security**, **Goal**, **Code** — с циклами до *полного* одобрения (исправляются даже NIT-находки) |
| принимают полуфабрикат | **QA** реально запускает тесты (и пишет свои); **Менеджер** трассирует начальные данные к конечным артефактам и выносит `ACCEPTED`/`REJECTED` |
| всё забывают к следующей сессии | **Саммарйзер** дистиллирует каждый принятый эпик в живую вики (`.ai/docs/`), которую читают агенты следующего эпика |
| игнорируют конвенции проекта | **Инициализатор** собирает актуальные лучшие практики по стеку в `.ai/guides/` и вписывает их в проектный `AGENTS.md` |

## Как это работает

```
/init-project (один раз на проект)
      │
      ▼
Инициализатор → Брифер → Архитектор → Техлид → Техписатель → Исполнитель
      │                                                        │
      │                            цикл ревью до полного одобрения:
      │                            Security → Goal → Code ──────┤
      │                                                        ▼
      │                     QA (QUALITY_PASSED) → Менеджер (ACCEPTED) → Саммарйзер → коммит
```

- **Главный агент координирует**: запускает субагентов, интерактивно рендерит их блоки вопросов (мультивыбор + свободный ввод), фиксирует статусы задач; коммитит только он.
- **Скилл `pipeline`** содержит правила координатора и подгружается по требованию («прогони конвейер», упоминание этапов, работа в проекте с артефактами `.ai/`).
- **Эскалации**: заблокированный агент возвращает структурированный маркер `!!! ESCALATION !!!`; координатор маршрутизирует его Техлиду-консультанту и возвращает обязывающее решение. Максимум одна эскалация на задачу у агента — угадывание является нарушением процесса.
- **Гейты этапов** зашиты в промпты каждого агента: нет брифа → нет архитектуры; нет декомпозиции → нет задач; нет одобренных ревью → нет QA; нет `ACCEPTED` → нет коммита.

## 12 агентов

| Агент | Роль | Выход / вердикт |
|---|---|---|
| `initializer` | Этап 0: определить/спросить стек, собрать актуальные лучшие практики | `.ai/guides/{tech}.md`, проектный `AGENTS.md` |
| `briefer` | Превратить любой запрос в финальный бриф через вопросы | `.ai/briefs/{epic}-brief.md` |
| `architect` | Спроектировать решение; дать обязательные рекомендации последующим | `.ai/architecture/{epic}-architecture.md` |
| `tech-lead` | Декомпозировать до задач (файлы задач не создаёт); решать эскалации | `.ai/decomposition/{epic}-decomposition.md` |
| `tech-writer` | Создать самодостаточные файлы задач из декомпозиции | `.ai/tasks/{epic}/{NN}-{name}-{date}.md` + `INDEX.md` |
| `developer` | Реализовать задачу строго по файлу; Phase 0 до правок; честная верификация | отчёт + статус `implemented` |
| `security-review` | Только реальные эксплуатируемые риски, с доказательствами | `PASS / PASS_WITH_WARNINGS / FAIL / NEEDS_MORE_CONTEXT` |
| `goal-review` | Трассировать каждый критерий приёмки к доказательству; ловить scope creep | `GOAL_MET / GOAL_PARTIALLY_MET / GOAL_NOT_MET / NEEDS_CONTEXT` |
| `code-review` | Корректность, граничные случаи, конвенции, гигиена диффа, целостность тестов | `APPROVE / REQUEST_CHANGES / NEEDS_DISCUSSION` |
| `qa` | Ревью покрытия тестов, реальные запуски, право писать свои тесты | `QUALITY_PASSED / QUALITY_FAILED / BLOCKED` |
| `manager` | Финальная приёмка: начальные данные против конечных артефактов | `ACCEPTED / REJECTED` + этап возврата |
| `summarizer` | После ACCEPTED: дистиллировать эпик в базу знаний | `.ai/docs/` вики + хроники + `INDEX.md` |

## Артефакты и статусы

Каждый проект получает след `.ai/`: `briefs/ · architecture/ · decomposition/ · tasks/{epic}/ (+INDEX.md) · reviews/ · qa/ · guides/ · docs/` (база знаний: `wiki/{component}.md`, `epics/{epic}-{date}/REPORT.md`, `INDEX.md`, `manual-checklist.md`).

Жизненный цикл задачи: `created → in_progress → implemented → reviewed → tested → accepted | rejected`.

Вики авторитетна, но проверяема: страницы несут штамп «проверено на коммите», а читателям предписано сверять утверждения с фактическим кодом.

## Установка

**Из маркетплейса (основной канал):**
1. ZCode → Plugin Marketplace → **Add → Add Plugin Marketplace** → вставьте URL этого репозитория.
2. **Personal → ZCode Pipeline → Install** → перезапустите сессию.
3. Проверка: 12 агентов, команда `/init-project`, скилл `pipeline`.

**Запасной канал (без маркетплейса):** откройте `zcode-pipeline-bundle.md` в ZCode и скажите «установи по этому документу» — он воссоздаст все файлы в user-scope.

## Использование

```
/init-project                                  # один раз на проект
"Прогони конвейер: добавь режим парольных фраз" # любая фича/фикс/рефакторинг
```

Дальше просто отвечайте на интерактивные раунды вопросов — порядок этапов, ревью, правки, статусы и коммиты ведёт конвейер.

## Структура репозитория и контрибуция

```
marketplace.json            # каталог маркетплейса (корень репо = маркетплейс)
zcode-pipeline/             # плагин (имя каталога == имени манифеста)
  .zcode-plugin/plugin.json
  agents/                   # 12 субагентов
  commands/init-project.md
  skills/pipeline/SKILL.md  # правила координатора
  assets/AGENTS-template.md # шаблон глобальных правил с плейсхолдерами персонализации
scripts/build_bundle.py     # сборщик бандла (самодостаточен от репо)
zcode-pipeline-bundle.md    # сгенерированный артефакт — не редактировать руками
```

Цикл обновления (коммиты и CHANGELOG на английском):
1. Правки только в `zcode-pipeline/{agents,commands,skills,assets}`.
2. Обновите `version` в `zcode-pipeline/.zcode-plugin/plugin.json` **и** запись плагина в `marketplace.json`.
3. `python3 scripts/build_bundle.py` (падает при утечке персональных данных или сломанной разметке — не обходить).
4. Коммит + запись в CHANGELOG; для вех — теги; `git push --follow-tags`.
5. Обновите плагин в ZCode → Settings → Plugins.
